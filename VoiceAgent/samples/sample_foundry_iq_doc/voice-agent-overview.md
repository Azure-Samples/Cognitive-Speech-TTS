# Azure AI Foundry Voice Agent

## Managed, real-time conversational voice experiences

Azure AI Foundry Voice Agent is a declarative agent capability for building natural, real-time voice
experiences without operating a custom voice-orchestration service. Customers configure the agent's
instructions, model, voice and audio behavior, tools, and optional greeting. Applications then connect to a
secure WebSocket endpoint to exchange live audio and events.

Foundry Agents manages the session and securely coordinates Azure Voice Live, the selected AI model, and
enterprise tools. The same agent configuration can be versioned, reused, and customized for individual
sessions.

## Key capabilities

| Area | Supported capabilities |
|---|---|
| **Natural conversation** | Bidirectional streaming audio, automatic turn detection, input noise reduction, input transcription, interruption and barge-in handling, and configurable response speed. |
| **Flexible model options** | Use a Voice Live-managed model or a model deployed in the customer's Foundry project. Both native speech-to-speech models and cascaded speech-to-text → language model → text-to-speech experiences are supported. |
| **Configurable personality** | Define reusable instructions and safely personalize them at session start with structured inputs. Optional greetings can use exact customer-authored text or be generated by the model. |
| **Voice and media controls** | Configure PCM or G.711 audio, supported Azure/OpenAI voice types, voice speed, voice activity detection, and audio or text output. Optional avatar configuration is supported where the selected transport and region provide avatar delivery. |
| **Enterprise tools and actions** | Call client-side functions, remote MCP servers, built-in controls such as ending a conversation, and Foundry toolbox tools such as Azure AI Search, web search, OpenAPI, A2A, file search, and other supported connectors. Foundry resolves configured connections and credentials for server-side tools. |
| **Agent lifecycle** | Create and manage immutable agent versions containing the model, instructions, audio settings, tools, greeting, and avatar defaults. Selected settings can be overridden for one session without changing the stored version. |
| **Behavior handoff** | On the stable `v1` protocol, a voice agent can move between configured specialist behaviors while preserving one continuous customer conversation. |
| **Optional conversation history** | Storage is off by default. When enabled, Foundry can retain transcripts, tool events, per-turn audio, and an on-demand stereo recording with the customer and agent on separate channels. |
| **Observability** | Customer-facing traces and metrics cover the full conversation, individual turns, speech/model stages, tool calls, latency, interruptions, token usage, and session outcomes. Telemetry can flow through the existing Foundry observability experience and customer Application Insights configuration. |

## How it works

**Client or application** ⇄ **secure Foundry Voice Agent WebSocket endpoint** ⇄ **Azure Voice Live** ⇄
**managed or customer-deployed model and configured tools**

The client sends microphone audio and receives synthesized audio plus standard real-time events. Foundry owns
session setup, model and tool authorization, configuration, tracing, and optional persistence; model and tool
credentials do not need to be exposed to the client.

## Example scenarios

- Customer support and service triage
- Virtual receptionists and appointment assistants
- Sales, outreach, and product guidance
- Travel and personal assistants
- Learning and coaching experiences
- In-vehicle or hands-free assistants

## Current scope and availability

- Voice Agent is a **preview capability**; availability, supported models, voices, avatars, and tools may vary
  by region and subscription enablement.
- The current first-party data-plane interface is **WebSocket**. Packaged PSTN/SIP telephony, WebRTC/Twilio
  ingress, and web/mobile widgets are separate deployment capabilities and may have different availability.
- Behavior handoff inside one voice agent is supported; cross-agent workflow handoff is not part of the
  current scope.
- Guided configuration generation, formal voice evaluation, and additional voice-specific content-safety
  controls are evolving capabilities.
